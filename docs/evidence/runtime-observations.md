# IDEA 界面只读观察记录

时间：2026-10-29，Asia/Shanghai。观察工具：`@oai/sky` Computer Use，Windows Graphics Capture / UI Automation。以下是实际屏幕观察的人工转录，不是 REA 的执行轨迹。

1. `sky.list_apps()` 返回已安装的 IntelliJ IDEA 2026.1.3，进程路径 `D:\Program Files\JetBrains\IntelliJ IDEA 2026.1.3\bin\idea64.exe`。已有一个项目窗口，最初最小化。先前 `Get-Process` 的空匹配不能证明该应用未运行。
2. 激活原有窗口后，顶部有仓库/项目选择器以及显示当前分支名的分支控件。只点击其向下箭头。
3. 分支弹窗实际显示：搜索分支和操作、更新项目（Ctrl+T）、提交（Ctrl+K）、推送（Ctrl+Shift+K）、新建分支（Ctrl+Alt+N）、签出标记或修订、最近、本地、远程；最近分支行右侧显示对应远程跟踪分支。没有点击任何会修改 Git 状态的条目。
4. Escape 关闭分支弹窗；Ctrl+K 只打开提交面板。刷新后的界面实际显示“提交 / 搁置”标签、“更改”分组及复选框、修改数、修正选项、提交消息编辑框、“提交”“提交并推送”按钮。现场没有“Staged / Unstaged”两组，因此当前项目展示的是更改选择式提交界面，不能将打包中存在的可选 Staging Area 说成当前已启用。
5. 没有点击文件内容或 Diff（当前改动是用户的配置文件），没有输入提交消息，没有执行暂存、提交、分支切换或任何远程操作。最后点击项目工具窗图标恢复项目面板。

边界：本次 UI 观察只证明入口和当前面板结构。它没有记录进程级 Git 命令，也没有验证 IDEA 写操作的结果。用户项目名称、文件内容和仓库 URL 不导出到此报告。窗口截图仅用于现场判断，没有把用户项目源码截图打包进交付物。

# HarborGit 1.9.3 · 拉取与合并提速

目标提交已经合入时，Pull 获取远程状态后直接返回，分支合并直接结束。两者都跳过工作区文件检查和无必要的 Stash 保存与恢复。

需要实际合并时，同一次检查中共享父目录结果，分批执行文件检查，并复用已经读取的目标文件清单。操作中的 Git 状态检查只读取当时所需的信息。Pull、Push 和分支合并完成后刷新分支列表，暂存与取消暂存完成后直接刷新工作区状态。手动刷新会更新完整列表。

## 本地耗时

Windows，Git 2.50.1，3,000 个跟踪文件，包含暂存、未暂存与未跟踪内容。Pull 使用本地裸仓库。测量 Git 服务从接收请求到返回状态的耗时，每项测两次并取平均。

| 场景 | 1.9.2 | 1.9.3 |
| --- | ---: | ---: |
| 有本地改动，需要合并 | 9.2 秒 | 4.4 秒 |
| 有本地改动，需要 Pull 更新 | 11.1 秒 | 5.2 秒 |
| 目标提交已合入，执行分支合并 | 10.7 秒 | 0.4 秒 |
| 目标提交已合入，执行 Pull | 12.1 秒 | 0.8 秒 |

这是本地样本的耗时。实际 Pull 还会受到网络传输、认证、仓库规模和本机 Git 的影响。[基准数据](verification-v1.9.3-benchmark.json)

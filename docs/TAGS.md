# 在 HarborGit 中打标签与推送（1.7.0）

先安装或启动 1.7.0。1.6.2 只有历史标签显示，没有本指南的创建、推送按钮。

## 标记当前提交

1. 打开仓库，点击左侧 **标签管理**。
2. 点击 **新建标签**，确认上方的目标提交。
3. 输入名称，例如 `v1.7.0`。默认“附注标签”，填写此次版本说明；也可以改为“轻量标签”。
4. 点击 **创建标签**。成功后回到本地标签列表。

附注标签会记录创建者和说明，使用当前 Git 身份；身份未配置时可通过左下方“提交身份”设置。轻量标签只引用目标提交，不记录说明和标签创建者。列表中附注标签显示标记时间，轻量标签显示提交时间。

## 标记以前的某次提交

点击 **提交历史 → 选择某次提交 → 创建标签**。确认对话框显示的提交说明与完整 ID，然后填写名称、类型和说明。无需切换分支或检出那个提交，也能给它打标签。

**标签只包含目标提交已有的代码。** 暂存、未暂存及未跟踪文件原样保留，不会被自动提交或放进标签。空仓库需要先完成首次提交。

## 推送标签

1. 在 **标签管理** 找到标签，点击右侧 **推送标签…**。
2. 确认标签和目标提交，选择远程，例如 `origin`，核对推送地址。
3. 点击 **推送标签**，等待成功提示。首次 HTTPS 连接可能打开系统 Git 凭据管理器；SSH 使用本机密钥。

没有远程仓库时，点击对话框内 **管理远程仓库地址** 添加配置，保存并关闭后回到列表重新选择推送。列表展示本地标签，尚不查询远程同步状态。

此入口只更新选中标签对应的远端引用，同时传输它依赖的提交和对象，不单独更新远端分支。顶部 **Push** 仍是分支推送入口；如果要精确推送一个 tag，请使用标签列表的按钮。普通分支 Push 是否附带可达附注标签，仍可能受到 Git 的 `push.followTags` 配置影响。

同名远程标签已经存在且指向不同对象时，Git 会拒绝推送，不进行覆盖。标签在确认期间被其他工具移动或删除时会要求刷新；关闭对话框、刷新列表后再检查。失败详情及执行命令可以在“操作日志”查看。长时间任务可在底部取消；取消发生时远端可能已经接受更新，应核实服务器结果后再重试。

## 发布 HarborGit 本身

先提交本次源码、`package.json` 与 `package-lock.json` 的版本号修改，再给**包含这些修改的提交**创建对应标签。例如版本 `1.7.0` 对应 `v1.7.0`。若工作区还有未提交的版本修改，直接给当前 HEAD 打标签会指向之前的代码。

将该标签推送到本项目 GitHub 远端后，现有工作流才会按标签执行构建与 Release 发布；创建本地标签本身不会发布。需要单独提交到分支的代码，可以先使用正常分支 Push。详情见 [更新与发布指南](UPDATES.md)。

## 当前范围

支持附注与轻量标签、指定提交、名称校验、重复名称拒绝、单标签推送、错误详情及取消。新建标签明确使用未签名模式，以保证类型不受 `tag.gpgSign` 设置改变。

暂不提供签名标签、标签删除或移动、强制推送、批量推送及远程标签浏览。已有指向非提交对象的标签也会列出，但界面只创建指向提交的标签。配置了多个推送地址的远程会提示暂不支持，避免在只确认一个地址时更新其他地址。

## 分析与实现的边界

IDEA 的菜单创建、历史提交创建、单标签推送和普通 Push 标签选项，来自本机 IDEA 插件资源及字节码静态证据，详见 [IDEA 标签调查](IDEA-TAGS-ANALYSIS.md)。REA 不直接支持 JVM class 分析，已按记录改用 JDK `javap`；这些证据不等同于 IDEA 真实远端操作验证。

HarborGit 的独立标签页面、双类型表单、固定对象检查、精确推送和现有异步任务整合为自行设计实现，未复用 IDEA 源码。测试仅操作专用测试仓库及本地裸仓库，未向真实 GitHub 仓库推送或发布。
